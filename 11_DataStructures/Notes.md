# 11. Структуры данных

- `Java Collections Framework` - это часть API Java для работы с коллекциями
- Включает:
    - Интерфейсы:(`List`, `Set`, `Map`, `Queue`)
    - Их реализации:(`ArrayList`, `HashSet`, `HashMap`, `TreeMap`)
    - Вспомогательные утилитные классы (`Collections`, `Arrays`)
- В основном размещены в пакете `java.util`

- `List` - когда важен порядок. Элементы по индексу.
- `Set` - когда важна уникальность.
- `Map` - когда важно нахождение значения по ключу. Ключи не повторяются

## Простой список List со строками

- [Простой список](src/List/ex01ListOfString)
- `List` и его реализации хранят элементы в порядке их добавления

```java
List<String> myList = new ArrayList<>();
```

- Для сортировки List нужен Comparator `sort(Comparator)`
- `Comparator` - это пользовательская реализация сортировки

- Для сортировки по алфавиту можно воспользоваться утилитарным методом sort для списков из пакета Colletions.
  `Collections.sort(list);`

### List с объектами

- Collections.sort(list) - не применится для списка с объектами
- Нужно как-то сообщить методу sort какое поле объекта использовать

#### Обобщенные типы

- Это большая безопасность типов
- Применяются чаще для создания типобезопасных коллекций
- Например, запрещает добавить Cat в список Dog
- Рассмотрим обобщенный класс ArrayList

```java
// Обобщенный класс. Использование параметра типа, определенного в объявлении класса
// Заполнитель типа <E> подставит везде соответствующий тип
public class ArrayList<E> extends AbstractList<E>
        implements List<E>, RandomAccess, Cloneable, java.io.Serializable {
    //...
}

// Обобщенный метод. Использование параметра типа, который не был определен в объявлении класса
// В обобщенный метод можно передавать подклассы Animal: Dog, Cat и др.
public <T extends Animal> void takeThing(ArrayList<T> list) {
    //...
}

// Обычный метод. Тут можно передавать только Animal (полиморфизм не сработает)
public void takeThing(ArrayList<T> list) {
    //...
}
```

- Другие обобщенные обозначения в docs java: `<T>` - type, `<E>` - element, `<R>` - return_type
- В обобщенных типах extends означает "Расширяет" + "Реализует"
- extends == "IS-A" (независимо что справа: интерфейс или класс)

#### Сортировка List объектов через Comparator и Comparable

- Comparable (внутреннее сравнение) Используется, когда класс сам определяет свой естественный порядок сортировки.
- Comparator (внешнее сравнение)   Используется, когда нужно различные способы сортировки без изменения самого класса.

- Пользовательский класс не реализует по-умолчанию интерфейс Comparable (в отличие от String)
- Соответственно метод Collections.sort(myList) не сработает для списка таких объектов
- **Вариант 1 Comparable: модифицировать класс объектов:**
    - В класс - объекты которого содержатся в списке нужно прописать implements Comparable<JukeboxStream.Song>
    - Далее переопределить метод compareTo()
    - Если это строки, и нам нужна сортировка по-умолчанию:, то можно использовать версию compareTo класса String не
      переписывая логику сравнения
    - [Пример компаратора класса](src/List/ex02ListOfObjects/Song.java)

- **Вариант 2 Comparator: Написать внешний компаратор**
    - Можно создать сколько угодно компараторов
    - Потом их использовать через `List.sort(Comparator c)`
    - Если передать в метод sort `внешний Сomparator `- то `compareTo() класса` не будет использоваться
    - Создается класс
    - [BMPCompare.java](src/List/ex02ListOfObjects/BMPCompare.java)
- **Вариант 3: Внутренние классы**
    - Аналогично Варианту 2 (просто реализация пишется в месте кода)
- **Вариант 4: Через лямбда-выражения**
    - Если интерфейс содержит 1 метод - его можно реализовать через лямбда-выражение
    - Comparator содержит 1 абстрактный метод - compareTo();
    - `myList.sort((one, two) ->one.getTitle().compareTo(two.getTitle()));`

### HashSet

- HashSet - это Set который использует хэш таблицу для быстрого поиска
- В Java есть 2 вида равенства: `Равенство ссылок` и `Равенство объектов`
- `Равенство ссылок` - это когда две ссылки указывают на один объект в куче
- `Равенство объектов` - это когда два объекта в куче по разным адресам, но идентичны
- HashSet наследует методы hashCode() и equals() от Object который устроен на "равенстве ссылок"
- Чтобы Set считал 2 объекта равными, нужно переопределить методы в классе, объекты которого помещаются в Сет
- В Object hashCode() формируется из адреса памяти в куче
- Поэтому hashCode будут формироваться разными для похожих объектов
- Чтобы дополнительно проверить содержимое - нужно проверить на идентичность через equals()
- Чтобы HashSet не содержал дубликатов "по содержимому" - нужно переопределить методы в классе equals() и hashCode()
- Эти методы срабатывают автоматически при добавлении объектов в HashSet
- Одинаковые хэш-коды не гарантируют что объекты равны (алгоритм hashCode() может выдать одинаковый результат для разных
  объектов)
- Дополнительно вызывается equals() для точного определения
- [Класс JukeboxStream.Song с переопределенными методами equals и hashCode()](src/HashSet/Song.java)

### TreeSet - если нужна сортировка в множестве (Set)

- `TreeSet` как и `HashSet` не допускает дублирование элементов
- Но элементы тут сохраняются в отсортированном виде
- По-умолчанию использует метод `compareTo()` каждого объекта (нужно реализовать `Comparable`)
- Если данный метод не реализован в классе объектов - то при добавлении второго элемента будет ошибка
- При добавлении второго элемента он пытается вызвать метод `compareTo()`
- Либо нужно использовать перегруженный конструктор, который принимает `Comparator` с методом `compare()`
- Можно передать свой `Comparator`  через Lambda
- Минус в том, что он тратит больше ресурсов даже когда сортировка не нужна
- [TreeSet](./src/TreeSet)

### Map - Словари

- Каждый элемент в словаре - это пара "ключ - значение"
- Значения могут повторяться, а ключи нет
- Ключами могут быть любые объекты Java

```java
// Создание словаря HashMap
Map<Integer, String> phones = new HashMap<>();
```

- put() - принимает 2 параметра: ключ и значение и помещает в словарь
- get() - принимает ключ и возвращает значение

## Фабричные методы для коллекций

- Convenience Factory - способ создать коллекцию: заранее заполненную данными
- Созданные фабричным методом коллекции нельзя изменить
- Такие коллекции не основаны на какой-то конкретной реализации ArrayList, HashSe или HashMap хоть и ведут себя в
  соответствии со своим интерфейсом
- Создание списка: List.of()
- Создание множества: Set.of()
- Создание словаря:
    - При добавлении до 10 записей можно использовать `Map.of()`
    - При добавлении более 10 записей используют `Map.ofEntries(Map.entry(), Map.entry(), ... Map.entry())`

### Полиморфизм в методах

- Если у нас есть метод, который принимает List<Animal> - то в этот метод нельзя передать List<Cat> или List<Dog>
- Тут не работает полиморфизм из соображения безопасности. Чтобы в список <Animal> не попали объекты другого типа
- Можно использовать метод с дженериками - он говорят компилятору: этот метод не будет добавлять новые элементы
- С содержимым списка работать можно: а добавлять что-либо уже нельзя

```java
// Передавай мне любые Animal, но добавлять я в него ничего не буду
public void takeAnimals(List<? extends Animal> animals) {
    for (Animal a : animals) {
        a.eat();
    }
}
```

```java
// Возвращаемый объект будет того же типа - что и передали  
public <T extends Animal> takeAnimals(List<T> list) {
}
```

### Обобщенные параметры в методах

- Дженерик (Generic) — это возможность создавать классы, интерфейсы и методы, которые работают с любыми типами данных,
  но при этом сохраняют типобезопасность на этапе компиляции.
- Проще говоря, это шаблон, где вы указываете: "Я буду работать с каким-то типом Т, а какой это тип — вы решите, когда
  будете создавать объект".
- До появления дженериков (Java 1.4 и ранее) все коллекции хранили объекты типа Object
