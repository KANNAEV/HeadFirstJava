# Наследование и Полиморфизм

## Наследование

- Наследование - принцип ООП, который позволяет создавать новые классы (потомки, подклассы) на основе уже существующих (
  родителей, супер-классов), перенимая их свойства и функциональность. Это механизм для повторного использования кода,
  создания естественных иерархий классов, отражающих отношения «является» (is-a) между объектами реального (или
  вымышленного Вами) мира.
- Подкласс расширяет супер класс.
- Подкласс `наследует` все публичные переменные и методы супер-класса.
- Подкласс `НЕ наследует` все приватные методы и переменные супер-класса.
- Унаследованные методы `можно` переопределять.
- Унаследованные переменные `нельзя` переопределять.
- Для проектирования иерархии наследования задай вопрос IS-A (является ли).
- Треугольник и квадрат являются фигурой, а кошка и собака - животным.
- Для вызова метода родительского класса в дочернем классе используется команда `super`. [Пример](./Cat.java)

## Полиморфизм

- Полиморфизм допускает что ссылка и объект могут иметь разные типы

```java
Animal myDog = new Dog();
// Тип ссылочной переменной объявлен как Animal
// Но объект создан как новый экземпляр класса Dog
```

- С помощью полиморфизма можно создавать массивы типа высшего класса и хранить в нем ссылки на объекты всех видов
  подтипов
- Можно описать метод принимающий тип родительского класса - и он сможет обработать так же и подтипы этого класса
- [Пример](./InherAndPolyTestDrive.java)

## Модификаторы доступа переменных

- `static final` - используется для констант. Такую переменную не изменишь.

## Доступ к членам класса при наследовании

- Уровни доступа к членам класса: `private` `default` `protected` `public`
- `public` - может унаследовать любой дочерний класс
- `private` - дочерние классы не унаследуют никогда
- `default` - доступ по умолчанию - в пределах того же пакета, где определен класс
- `protected` - доступ в пределах одного пакета, + из других пакетов. Работает только через наследование

## Заключение контракта при наследовании методов

- Переопределяя метод полученный от родительского класса - мы должны соблюдать контракт
- Аргументы и возвращаемые значения внешне должны выглядеть одинаково

## Перегрузка методов

- Перегрузка метода - это наличие нескольких методов с одним и тем же именем
- Но с разным набором аргументов.
- Новый метод не обязан выполнять контракт перегружаемого метода
- Потому можно так же изменить уровень доступа
